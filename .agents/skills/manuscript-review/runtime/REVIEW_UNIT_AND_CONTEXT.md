# 审核单位与上下文契约

> 本文件解决一个根本问题：**审“一章”还是审“一幕/一个序列”？**
>
> 结论：**单章只能做局部诊断；要判断“好不好看”，至少要看一个序列（3–8 章）或一幕（约 8–30 章），并带上足够的前情/幕纲/人物卡/文风参考。**

## 0. 为什么单章不够

单章能判断的：

- 这一章的场景/对白/语言执行；
- 这一章自身的功能是否完成；
- 这一章内部的局部因果、局部人物反应、局部信息交付。

单章**不能**可靠判断的：

- 这一幕有没有重大逆转、中点、危机、高潮；
- 主角的求索/人物弧是否成立；
- 伏笔是否回收、承诺是否兑现；
- 跨章人物状态、关系变化、承诺/回收、节奏；
- 节奏是否拖/跳、章功能分布是否合理；
- 这一章在整幕/整卷里到底承担什么。

> 把单章当“整幕”评，会得出两种误判：把铺垫章骂成“没进展”，把高潮章夸成“全幕都好”。

## 1. 审核单位

| 单位 | 范围 | 能判 | 不能判 | 报告标签 |
|---|---|---|---|---|
| **单章 `chapter_local`** | 1 章 | 局部场景、对白、语言、本章功能 | 幕逆转、人物弧、求索、伏笔回收、跨章因果、整幕节奏 | **局部诊断** |
| **序列 `sequence`**（推荐最低） | 3–8 章 | 序列目标/转折、章功能分布、局部弧、承诺/回收、序列节奏 | 全幕/全书弧、最终高潮 | **序列级** |
| **幕 `act`**（推荐） | 约 8–30 章 / 一卷一幕 | 幕功能、激励、渐进复杂化、中点、危机、高潮、收束、跨章因果、人物弧 | 全书/多卷 | **幕级** |
| **多幕/卷 `multi_act`** | 多幕/整卷 | 跨幕结构、卷级弧、长线 | 全书终局（除非给全稿） | **卷/多幕级** |
| **序章/引子** | 1 章或短序列 | 建立缺失/悲剧/世界规则/悬念、交棒 | 主角弧、整幕逆转 | **序章级**（见 `STORY_CRAFT_LENS.md` §13） |

**默认建议**：至少一个序列（3–8 章）或一幕。用户只给一章时，不要假装能评整幕。

## 2. 审核单位门（先问再审）

素材交接门之后、Phase 1 之前，如果用户没有明确说“只审这一章/局部诊断”，主持必须先问一次：

> 这次想审一章，还是一幕/一个序列？建议至少给一个序列（3–8 章）或一幕，外加这一幕的前情/大纲；只给一章的话，我只能做局部诊断，不能判断幕逆转、人物弧、求索、伏笔回收、跨章因果。

规则：

- **用户给文件夹**：先列章节，确认“这是哪一幕/哪个序列”；不要默认只审第一章。
- **用户给多章但没分幕**：按章节功能/转折提出序列/幕切分，让用户确认；不要自己硬切后不说明。
- **用户给一幕但没有前情/大纲**：先问“这一幕的前情、后续、幕纲有没有？”没有则降置信度，标“跨章判断受限”。
- **用户只给一章且坚持**：进入 `chapter_local`，报告标题写“局部诊断”，不写“幕级总分”；幕级 craft 项标 N/A。
- **用户说“就这一章，但我想要幕级结论”**：明确拒绝“单章推全幕”；可以给“如果这一幕后续按 X 发展，则……”的条件判断，标 `[推断]`。
- **序章/引子**：按序章特例评，不拿主角第一幕的尺子量。

## 3. 上下文包

审一幕/序列时，至少要有：

| 层级 | 内容 | 缺失后果 |
|---|---|---|
| **必需** | 本单位的正文（完整章节） | 无法审 |
| **强烈建议** | 前情摘要/上一幕结尾；人物当前状态；未回收承诺 | 跨章因果、人物状态、伏笔回收只能猜 |
| **强烈建议** | 本幕/本序列的幕纲/大纲：这一幕要完成什么、在哪里转折、结尾要留下什么 | 无法判断“这一幕是否完成功能” |
| **建议** | 人物卡、关系表、文风样本 | 人物声音/关系/语气判断受限 |
| **可选** | 后续摘要/下一幕开头（防未来泄漏，可只给“这一幕该埋什么”） | 无法判断铺垫是否有效 |
| **可选** | 平台/类型/目标读者/字数要求 | 类型契约判断受限 |

**上下文置信度**：

- **高**：单位完整 + 前情/幕纲 + 人物卡/文风参考 + 目标读者；
- **中**：单位完整 + 部分前情/人物卡；跨章判断有保留；
- **低**：只有单位正文；只能做单位内自洽 + 局部诊断；不能给幕级强结论。

报告必须写清：**这次能判什么、不能判什么。**

## 4. 单位地图（Phase 0）

审一幕/序列时，先建一张“单位地图”，不是只建单章地图：

### 4.1 单位信息

- 单位类型：序列/幕/多幕/序章/单章局部；
- 章节范围、字数、POV 分布、时间跨度；
- 这一幕在卷/全书里的功能：开局、推进、转折、揭示、蓄势、收束、换地图；
- 这一幕的“输入状态”和“输出状态”：人物、关系、信息、资源、局势。

### 4.2 章节功能表

| 章 | 标题/功能 | POV | 时间/地点 | 关键事件 | 本章转折 | 对幕的贡献 | 字数 |
|---|---|---|---|---|---|---|---|
| 1 | | | | | | | |

要判断：每章是否有独立功能？有没有重复功能/空转章？章与章之间是因果还是并列？

### 4.3 序列地图

| 序列 | 章范围 | 目标 | 障碍 | 转折 | 结果 | 功能 |
|---|---|---|---|---|---|---|
| 1 | | | | | | |

### 4.4 幕结构

- **幕开场**：从什么状态开始？读者需要知道什么？
- **激励事件**：什么事件打破平衡、迫使主角行动？
- **渐进复杂化**：阻力如何升级？主角的选择如何变少/代价如何变高？
- **中点**：什么重大逆转/揭示改变方向？
- **危机**：最大压力下的两难是什么？
- **高潮**：主角做出什么选择？代价是什么？
- **收束/新平衡**：什么不可逆地改变？留下什么新问题？
- **幕末钩子**：下一幕的期待是什么？

不是每一幕都必须套满这些节点；先问“这一幕的功能需要哪些”，再判断“该有的有没有做好”。

### 4.5 贯穿线

- **求索/脊椎**：本幕主角想要什么？这个目标在章与章之间如何推进/受阻？
- **赌注升级**：失败会失去什么？从第一幕到最后一章，赌注如何变具体/变高？
- **人物弧**：主角/核心人物的价值、关系、认知在本幕开始/结束有什么变化？
- **关系线**：谁对谁的关系变了？方向性、互惠、亏欠、敌意是否连续？
- **信息线**：谁知道什么？读者/人物/世界真相的信息差如何变化？
- **承诺/回收**：本幕埋了什么、回收了什么、悬置了什么？

### 4.6 跨章推进（写作技巧）

- 人物状态：伤势、疲劳、关系、认知是否让读者跟得上？
- 选择/后果：上一章的选择是否让下一章更有张力？
- 承诺/回收：前面的铺垫是否在后面被使用/回收？有没有“提到就忘”？
- 章功能分布：是否有起伏？有没有连续高压/连续蓄势？
- 读者记忆：跨章之后，读者还记不记得关键人物/目标/威胁？

## 5. 单章局部诊断（chapter_local）

用户只给一章、且明确接受局部诊断时：

**可以做**：

- 本章场景/对白/语言执行；
- 本章内部因果、人物反应、信息交付；
- 本章功能是否完成（只按本章承诺判断）；
- 本章与前情的人物状态、语气、关系是否接得上。

**不能做**：

- 幕逆转、中点、高潮、收束；
- 主角求索/人物弧的整幕判断；
- 伏笔是否回收、承诺是否兑现；
- 跨章节奏、章功能分布；
- “这一幕好不好看”的幕级结论。

**报告写法**：

- 标题：“局部诊断：第 X 章”；
- 分数：“局部诊断分（不可作幕级结论）”；
- Craft Scorecard：只填能局部判断的项，幕级项标 `N/A（需整幕）`；
- 明确列出“本次不能判断”的清单；
- 如果用户想要幕级结论，建议补章/前情/幕纲。

## 6. 序章/引子

序章/引子按 `STORY_CRAFT_LENS.md` §13 评：

- 不要求 POV 角色完成成长弧；看“揭示/悲剧/债源”；
- 不要求序章 POV 拥有完整主线求索；看“建立缺失并交棒”；
- 重点看：读者契约（是否标明序章）、世界规则/悬念、章末交接。

## 7. 覆盖与置信度

报告必须附“覆盖矩阵”：

| 项目 | 覆盖情况 | 影响 |
|---|---|---|
| 本单位正文 | 完整/缺章/节选 | |
| 前情 | 有摘要/有原文/无 | |
| 幕纲/大纲 | 有/无 | |
| 人物卡/文风参考 | 有/部分/无 | |
| 后续 | 有摘要/无 | |
| 平台/类型 | 有/无 | |

**置信度**：

- 高：单位完整 + 前情/幕纲 + 人物卡/文风参考；
- 中：单位完整 + 部分上下文；
- 低：只有单位正文或节选；只给局部结论。

## 8. 失败处理

- **用户只给一章**：先过单位门；用户坚持才做 `chapter_local`，并写清不能判断什么。
- **用户给一幕但缺章**：列出缺章；缺章影响跨章判断，降置信度。
- **用户给一幕但没有幕纲**：按章节功能反推幕结构，标 `[推断]`；不要假装知道作者意图。
- **用户给整卷**：先按幕/序列切分，确认审哪几幕；不要一次吞整卷。
- **用户给的是片段/节选**：标“片段诊断”，不判断整章/整幕功能。
- **单位太长**：按序列分批审，每批 3–8 章；最后给幕级汇总。
- **用户要“一章定全幕”**：拒绝；给条件判断或建议补材料。
